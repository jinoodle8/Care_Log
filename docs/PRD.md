# CareLog PRD (제품 요구사항 문서)

> 본 문서는 `CLAUDE.md` 1장(프로젝트 개요)·5장(MVP 기능 범위)을 기반으로 화면 단위 요구사항과 수용 기준(Acceptance Criteria)을 구체화한다.
> 대상 독자: 기획/개발/QA. 코드 구현 전 승인이 필요한 최상위 요구사항 문서.

---

## 1. 제품 개요

- **한 줄 정의**: 스마트폰 카메라와 비전 AI로 어르신의 복약 '행동'을 인식·기록하고, 보호자(자녀)에게 실시간으로 증명하는 플랫폼.
- **비즈니스 목표**: 어르신의 조작 부담을 "앱 실행 1회"로 최소화하면서, 보호자에게는 신뢰 가능한 복약 증거(영상 기반 판정)를 제공한다.
- **비대상(Out of Scope)**: 약물 성분 분석, 복약 지도, 진단성 문구 — 본 서비스는 **비의료 서비스**이며 "보호자 알림"까지만 제공한다. (CLAUDE.md 7장)

## 2. 페르소나 및 사용 시나리오

### 2.1 SERVICE USER — 어르신 (70대, 독거)
- **특징**: 스마트폰 조작에 익숙하지 않음. 복잡한 UI/다단계 조작 불가.
- **목표**: "약을 먹었다"는 사실을 최소 동작으로 남기고 싶다.
- **핵심 시나리오**: 아침 식후, 앱을 켠다 → 3초 후 자동으로 녹화가 시작된다 → 평소처럼 약을 먹는다 → 앱이 알아서 "복약 완료! 따님께 알려드렸어요"라고 말해준다.

### 2.2 SERVICE BUYER — 보호자 (4050, 직장인 자녀)
- **특징**: 바쁜 일과 중 짧은 시간에 부모님 상태를 확인하고 싶어함.
- **목표**: 부모님이 약을 제때 챙겨 드셨는지 실시간으로, 그리고 나중에 이력으로 확인하고 싶다.
- **핵심 시나리오**: 출근길에 "복약 완료" 푸시를 받는다 → 궁금할 때 대시보드에서 오늘/이번 주 이행률을 확인한다 → 애매한 건(UNCERTAIN)은 직접 영상을 보고 확인 처리한다.

## 3. 핵심 플로우 (End-to-End)

1. 어르신이 앱 실행 (역할은 최초 온보딩 시 보호자가 설정, 이후 자동 분기)
2. 3초 카운트다운 → 자동 녹화(최대 15초)
3. AI 분석 (얼굴·알약·손 인식 + 복약 행동 시퀀스 판별) — Mock 단계에서는 `MockRecognitionEngine`
4. 판정 정책 적용:
   - `sequenceConf ≥ 0.90` → `TAKEN` 자동 기록
   - `0.60 ≤ sequenceConf < 0.90` → `UNCERTAIN` (보호자 수동확인 요청)
   - `sequenceConf < 0.60` → `MISSED`
5. 서버에 로그 업로드 (영상은 S3, 로그는 DB)
6. 보호자 앱에 WebSocket 실시간 반영 + Expo Push 발송
7. (UNCERTAIN인 경우) 보호자가 영상을 확인하고 수동으로 확인/미복용 처리

## 4. 화면 단위 요구사항

### 4.1 공통

#### 4.1.1 온보딩 / 역할 분기
- **설명**: 앱 최초 실행 시 로그인/역할(어르신·보호자) 결정. 어르신 계정은 보호자가 대신 세팅하는 흐름을 기본으로 한다.
- **수용 기준**:
  - [ ] 최초 실행 시 "보호자로 시작" / "초대코드로 어르신 기기 설정" 두 경로 제공
  - [ ] 보호자는 회원가입 후 초대코드를 생성할 수 있다
  - [ ] 어르신 기기에서 초대코드 입력(또는 보호자가 대리 입력) 시 어르신 계정이 생성되고 해당 기기는 "어르신 모드"로 고정된다
  - [ ] 이후 앱 재실행 시 로그인 화면 없이 고정된 모드로 즉시 진입한다 (어르신 기기 기준)

---

### 4.2 어르신 모드 (극단적 단순화)

#### 4.2.1 홈 화면
- **설명**: 초대형 "약 먹기" 버튼 1개만 존재. 글씨 크기 최소 28pt 이상, 버튼 터치 영역 화면의 60% 이상.
- **수용 기준**:
  - [ ] 화면에 보이는 상호작용 요소는 버튼 1개(+ 오늘 스케줄 간단 표시)뿐이다
  - [ ] 버튼 텍스트는 "약 먹기" 등 5자 이내의 큰 글씨
  - [ ] 버튼 터치 시 카메라 권한이 없으면 권한 요청 → 거부 시 재요청 안내 화면(글씨 크고 단순한 문구)

#### 4.2.2 카운트다운 / 녹화 화면
- **설명**: 버튼 터치 후 3초 카운트다운, 이후 자동 녹화 시작(최대 15초), 별도 조작 없이 자동 종료.
- **수용 기준**:
  - [ ] 3초 카운트다운은 숫자 애니메이션 + 음성/사운드 안내(선택)로 표시된다
  - [ ] 카운트다운 종료 즉시 자동 녹화가 시작되며 사용자의 추가 터치 없이 진행된다
  - [ ] 녹화는 최대 15초 후 자동 종료되거나, 판정 로직이 충분한 시퀀스를 확보하면 조기 종료될 수 있다 (Mock 단계는 고정 길이로 시뮬레이션)
  - [ ] 녹화 중 화면에는 "촬영 중" 표시와 취소(뒤로가기) 옵션만 존재

#### 4.2.3 분석 중 화면
- **설명**: 녹화 종료 후 AI 분석 대기 화면.
- **수용 기준**:
  - [ ] "확인하고 있어요..." 등 단순 문구 + 로딩 인디케이터 표시
  - [ ] Mock 엔진 기준 3~5초 내 결과로 전환된다
  - [ ] 분석 중 네트워크 오류 발생 시 재시도 버튼(큰 글씨) 제공

#### 4.2.4 결과 화면
- **설명**: 판정 결과에 따라 다른 메시지와 Bounding Box + 신뢰도 오버레이(디버그/시연용, mock 데이터 기반)를 표시.
- **수용 기준**:
  - [ ] `TAKEN`: "복약 완료! 따님께 알려드렸어요" 류의 긍정 메시지
  - [ ] `UNCERTAIN`: "확인 중이에요. 따님이 곧 확인할 거예요" 류의 중립 메시지 (재촬영 유도는 하지 않음 — MVP는 보호자 수동확인에 위임)
  - [ ] `MISSED`: 결과 화면에서도 진단적/질책성 문구 금지, 단순 안내만
  - [ ] Bounding Box·신뢰도 오버레이는 mock `RecognitionResult.detections` 데이터를 화면 중앙 근처에 렌더링한다
  - [ ] 결과 화면에서 홈으로 돌아가는 동작은 버튼 1개(또는 자동 타임아웃 후 복귀)

#### 4.2.5 복약 스케줄 알림 수신
- **설명**: 보호자가 설정한 아침/점심/저녁 스케줄에 맞춰 알림을 수신한다.
- **수용 기준**:
  - [ ] 스케줄 시각에 로컬/푸시 알림이 발송된다
  - [ ] 알림 문구는 단순 명료("점심약 드실 시간이에요")
  - [ ] 알림 탭 시 홈 화면(약 먹기 버튼)으로 즉시 이동

#### 4.2.6 내 복약 기록 (M7)
- **설명**: 어르신이 자기 복약 기록을 직접 확인한다. 보호자 타임라인과 달리 통계·그래프 없이
  "언제 드셨는지"만 큰 글씨로 보여준다.
- **설계 원칙**: 홈 화면의 "약 먹기" 버튼 크기·위치는 그대로 두고, 그 아래 보조 버튼으로 진입한다.
  어르신 모드의 상호작용 요소가 늘어나는 것이므로 최소한으로 유지한다(CLAUDE.md 5장).
- **수용 기준**:
  - [ ] 최근 7일 기록을 날짜별로 묶어 최신순으로 보여준다
  - [ ] 각 항목은 "8월 12일 아침 · 드셨어요" 수준의 한 줄 문구, 글씨 24pt 이상
  - [ ] `TAKEN`/`UNCERTAIN`/`MISSED`를 각각 "드셨어요" / "확인 중이에요" / "기록이 없어요"로 표기한다
  - [ ] 질책성·진단성 문구를 쓰지 않는다("거르셨습니다", "위험" 등 금지)
  - [ ] 기록이 없으면 "아직 기록이 없어요"만 표시한다
  - [ ] 홈으로 돌아가는 버튼 1개

#### 4.2.7 어르신 설정 (M7)
- **설명**: 어르신 기기에서 바꿀 수 있는 것은 최소한으로 둔다. 계정 정보 관리는 보호자가 대신한다.
- **설계 원칙**: 홈 화면 구석의 작은 진입점으로만 접근한다. 어르신이 실수로 들어가 설정을
  망가뜨리지 않도록 파괴적 동작(연동 해제·계정 삭제)은 두지 않는다.
- **수용 기준**:
  - [ ] 내 이름·전화번호를 확인할 수 있다(수정은 가능하되 기본은 읽기 화면)
  - [ ] 연동된 보호자 이름을 확인할 수 있다
  - [ ] 알림 권한 상태를 보여주고, 꺼져 있으면 설정으로 이동하는 버튼을 제공한다
  - [ ] 로그아웃·계정 삭제·연동 해제는 노출하지 않는다

---

### 4.3 보호자 모드

#### 4.3.1 어르신 계정 연동
- **설명**: 초대코드로 어르신 계정을 연동. 한 어르신에 다수 보호자 연동 가능(다대다).
- **수용 기준**:
  - [ ] 초대코드는 일정 시간(예: 24시간) 후 만료된다
  - [ ] 동일 어르신에 최소 2인 이상의 보호자가 연동 가능함을 확인할 수 있다
  - [ ] 연동된 어르신이 없으면 대시보드 대신 "연동하기" 안내 화면을 보여준다

#### 4.3.2 대시보드 (오늘의 복약 현황)
- **설명**: 시간대별(아침/점심/저녁) TAKEN/UNCERTAIN/MISSED 카드.
- **수용 기준**:
  - [ ] 각 시간대 슬롯의 상태가 색상+텍스트로 구분되어 표시된다 (예: 완료/확인필요/미복용/예정)
  - [ ] 다중 어르신 연동 시 어르신 전환 UI 제공
  - [ ] 새로고침 없이 WebSocket으로 실시간 상태 갱신 (테스트: 어르신 기기에서 복약 완료 시 3초 이내 대시보드 반영)

#### 4.3.3 복약 타임라인
- **설명**: 일/주 단위 이력과 이행률(%) 그래프.
- **수용 기준**:
  - [ ] 일 단위: 해당 일자의 개별 로그 리스트(시각, 판정 결과) 표시
  - [ ] 주 단위: 요일별 이행률 막대/라인 그래프 표시
  - [ ] 이행률 = TAKEN 건수 / (전체 스케줄 건수) 로 계산, 계산식이 화면 내 확인 가능해야 함(툴팁 등)

#### 4.3.4 실시간 푸시 알림
- **설명**: 복약 완료, 미복용(스케줄 +30분 경과), 수동확인 요청 3종.
- **수용 기준**:
  - [ ] 복약 완료(`TAKEN`) 시 푸시 발송 — 목표 지연 ≤ 3초(성능 목표는 실모델 단계 재검증)
  - [ ] 스케줄 시각 +30분 경과 후에도 로그가 없으면 "미복용 의심" 푸시 발송 (크론 기반)
  - [ ] `UNCERTAIN` 판정 시 "수동확인 요청" 푸시 발송
  - [ ] 푸시 탭 시 해당 로그/대시보드 화면으로 딥링크 이동

#### 4.3.5 UNCERTAIN 수동확인
- **설명**: `UNCERTAIN` 로그에 대해 보호자가 영상을 보고 확인/미복용 처리.
- **수용 기준**:
  - [ ] 목록에서 `UNCERTAIN` 항목만 필터링 가능
  - [ ] 항목 탭 시 영상 재생(S3 presigned URL) + 판정 근거(신뢰도, 시퀀스) 표시
  - [ ] "복약 확인" / "미복용 처리" 두 버튼 중 선택 시 로그의 `manualConfirmedBy`, `decision`이 갱신된다
  - [ ] 처리 완료 후 어르신 측에는 진단성 피드백을 보내지 않는다(정책상 보호자 알림까지만)

#### 4.3.6 복약 스케줄 설정
- **설명**: 보호자가 어르신 대신 아침/점심/저녁 스케줄을 설정.
- **수용 기준**:
  - [ ] 슬롯별(아침/점심/저녁) 시각 설정 및 on/off 가능
  - [ ] 저장 즉시 어르신 기기의 알림 스케줄에 반영(다음 알림부터 적용)
  - [ ] 다중 보호자가 동시에 수정할 경우 마지막 저장이 반영됨을 명시(낙관적 동시성, 별도 충돌 UI는 MVP 범위 밖)

#### 4.3.7 보호자 설정 (M7)
- **설명**: 보호자가 자기 계정과 연동 관계를 관리한다. 어르신 계정 정보도 여기서 대신 수정한다.
- **수용 기준**:
  - [ ] **내 정보**: 이름·전화번호 수정. 전화번호는 형식 검증 후 중복이면 명확한 에러 표시
  - [ ] **비밀번호 변경**: 현재 비밀번호 확인 후 변경. 현재 비밀번호가 틀리면 변경되지 않는다
  - [ ] **연동된 어르신**: 목록 표시, 각 어르신의 이름·전화번호 수정, 초대코드 추가 발급
  - [ ] **알림 설정**: 복약 완료/미복용/수동확인 요청 3종을 각각 on/off. 끈 종류는 푸시가 발송되지 않는다
  - [ ] **로그아웃**: 저장된 토큰을 지우고 온보딩으로 돌아간다
  - [ ] **계정 삭제**: 확인 절차(문구 입력 또는 2단계 확인) 후 계정과 연동을 삭제한다.
        어르신의 복약 기록은 다른 보호자가 남아 있으면 유지하고, 마지막 보호자면 함께 삭제한다
  - [ ] 파괴적 동작(계정 삭제)은 되돌릴 수 없음을 사전에 명확히 고지한다

## 5. 비기능 요구사항

- **접근성**: 어르신 모드는 WCAG AA 이상 대비, 최소 폰트 크기 28pt, 터치 영역 최소 88x88pt.
- **성능(실모델 단계 목표, 사업계획서 기준)**: 객체 인식 mAP@0.5 ≥ 0.95, 프레임당 ≤ 33ms, 시퀀스 분류 정확도 ≥ 95%·FPR ≤ 3%, 최종 판정 정확도 98%, 푸시 지연 ≤ 3초. Mock 단계에서는 해당 목표를 측정하지 않고 서비스 플로우 완성도만 검증한다.
- **개인정보/보안**: 영상 원본은 S3에만 저장(DB 미저장), 서버측 AES-256 암호화(SSE), 기본 30일 수명주기. 개인정보 평문 로깅 금지.
- **가용성**: WebSocket 연결 끊김 시 폴링 폴백 또는 재연결 로직 필요(TRD에서 상세화).

- 약물 성분 분석·복약 지도·진단성 문구
- Mock 단계에서 실모델 라이브러리 선탑재
- 영상 원본 DB 저장, 개인정보 평문 로깅
